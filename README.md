# DemandLens — Retail Demand Forecasting & Inventory Intelligence

DemandLens is a retail demand forecasting and inventory intelligence system.
It is built on the Walmart M5 competition dataset for Store CA_1 (3,049 items).
It trains LightGBM models for 7-day and 28-day future sales horizons.
It finds sales anomalies using clustering and Isolation Forest algorithms.
It gives store managers smart reorder advice with safety stock calculations.

The web dashboard lets users pick an item, choose a pretend "Today" date, inspect forecasts, review past anomalies, and calculate replenishment orders.

## 2. Files That Are Not in Git (Large Handover Files)

Large dataset files and trained models are not committed to git.
They are generated by **Notebook 10** (`DLens_10_Backend_Data_Export.ipynb`) and shared in Google Drive inside the folder **`for_backend`**.

Download the files from `for_backend` and place them into the exact folders shown below:

| File Name | Destination Folder | Description |
| :--- | :--- | :--- |
| `lightgbm_h7.joblib` | `backend/models/` | Trained LightGBM model for 7-day horizon |
| `lightgbm_h28.joblib` | `backend/models/` | Trained LightGBM model for 28-day horizon |
| `feature_lists.json` | `backend/data/` | Feature column lists and item category index |
| `history_small.parquet` | `backend/data/` | Historical daily sales for CA_1 items up to validation start |
| `calendar_small.csv` | `backend/data/` | Calendar dates, day offsets, events, and SNAP flags |
| `anomalies_validation.parquet` | `backend/data/` | Pre-computed anomaly records for validation period |
| `item_groups.csv` | `backend/data/` | K-Means demand cluster labels per item |
| `group_thresholds.csv` | `backend/data/` | Threshold values per cluster for rule-based flags |
| `item_error_spread.csv` | `backend/data/` | Typical daily prediction error per item for safety stock |

*(Note: `anomalies_test.parquet` is created in notebook 10 for offline analysis. The backend code does not load it to prevent future test leakage.)*

Alternatively, you can place all these files together in a top-level folder named `backend handover/` at the repository root. `backend/config.py` automatically checks both locations.

## 3. Environment Setup

### Required Runtimes
- **Python:** 3.10 to 3.12 (matching Google Colab)
- **Node.js:** 18 or higher (tested on Node v20 / v24)
- **npm:** 9 or higher

### Step 1: Clone and Set Up Python Backend
Open a terminal in the project root:

```bash
# 1. Navigate to backend directory
cd backend

# 2. Create a virtual environment
python -m venv venv

# 3. Activate the virtual environment
# On Windows PowerShell:
.\venv\Scripts\Activate.ps1
# On macOS / Linux:
source venv/bin/activate

# 4. Install backend dependencies
pip install -r requirements.txt
```

### Step 2: Set Up React Frontend
Open a second terminal window in the project root:

```bash
# 1. Navigate to frontend directory
cd frontend

# 2. Install JavaScript packages
npm install
```

## 4. How to Start the Application

### Start the Backend Server
In your backend terminal (with virtual environment activated):

```bash
cd backend
python app.py
```
- The backend starts on: **`http://localhost:5000`**
- It runs with `host="0.0.0.0"` and `port=5000`.
- Verify the server is running by opening: `http://localhost:5000/api/health`

### Start the Frontend Web App
In your frontend terminal:

```bash
cd frontend
npm run dev
```
- The frontend starts on: **`http://localhost:5173`**
- Open your browser and visit: `http://localhost:5173`

### Connecting Frontend to Backend (Real API vs Mock Data)
- **Backend URL:** Configured in `frontend/src/services/api.js` via the environment variable `VITE_API_BASE_URL`. Default is `http://localhost:5000/api`. You can create `frontend/.env` to customize it:
  ```text
  VITE_API_BASE_URL=http://localhost:5000/api
  ```
- **Automatic Fallback:** The frontend automatically calls the live backend API. If the backend is stopped or unreachable, the frontend falls back to built-in mock data in `frontend/src/data/mockData.js`. A yellow "DEMO DATA" banner will appear at the top with a "Retry API" button.

## 5. API Reference

All backend endpoints are prefixed with `/api` (or accessed bare).

### 1. Root & Health Check
- **Route:** `GET /api/health`
- **Description:** Checks if the server is up and models are loaded into memory.
- **Example Response (200 OK):**
  ```json
  {
    "status": "ok",
    "models_loaded": true,
    "items_count": 3049
  }
  ```
- **Example Response (503 Service Unavailable when files missing):**
  ```json
  {
    "status": "error",
    "message": "Backend models and datasets are not ready yet.",
    "models_loaded": false
  }
  ```

### 2. Diagnostic Status
- **Route:** `GET /debug/status`
- **Description:** Reports the presence of all required model and data files.
- **Example Response:**
  ```json
  {
    "status": "ready",
    "models_loaded": true,
    "missing_files": []
  }
  ```

### 3. Items List
- **Route:** `GET /api/items`
- **Description:** Returns the list of 3,049 items for the header selector.
- **Example Response:**
  ```json
  {
    "count": 3049,
    "items": [
      {
        "item_id": "FOODS_1_001_CA_1",
        "department": "FOODS_1",
        "group": "Low_Intermittent"
      }
    ]
  }
  ```

### 4. Demand Forecast
- **Route:** `GET /api/forecast?item_id=FOODS_1_001_CA_1&today=2016-04-24`
- **Parameters:**
  - `item_id` (string, required): Item identifier.
  - `today` (date string `YYYY-MM-DD`, required): Pretend date between `2016-03-28` and `2016-04-24`.
- **Example Response:**
  ```json
  {
    "item_id": "FOODS_1_001_CA_1",
    "today": "2016-04-24",
    "history": [
      { "date": "2016-04-18", "sales": 2.0 },
      { "date": "2016-04-19", "sales": 1.0 }
    ],
    "forecast_7": [
      { "date": "2016-04-25", "value": 1.4 },
      { "date": "2016-04-26", "value": 1.1 }
    ],
    "forecast_28": [
      { "date": "2016-04-25", "value": 1.2 },
      { "date": "2016-04-26", "value": 1.0 }
    ]
  }
  ```

### 5. Anomaly Detection
- **Route:** `GET /api/anomalies?today=2016-04-24&item_id=FOODS_1_001_CA_1`
- **Parameters:**
  - `today` (date string `YYYY-MM-DD`, required): Cutoff date.
  - `item_id` (string, optional): Specific item to filter.
- **Example Response:**
  ```json
  {
    "count": 1,
    "anomalies": [
      {
        "item_id": "FOODS_1_001_CA_1",
        "date": "2016-04-10",
        "sales": 12.0,
        "forecast": 2.3,
        "direction": "spike",
        "reason": "price change",
        "flagged_by": "both"
      }
    ]
  }
  ```

### 6. Inventory & Reorder Advice
- **Route:** `POST /api/reorder`
- **Body JSON:**

## 6. 5-Step Live Demo Script

Follow these steps for a live five-minute presentation:

1. **Start Services:** Start the Flask backend (`python app.py`) and Vite frontend (`npm run dev`). Open `http://localhost:5173`.
2. **Set Pretend Date:** In the top header date picker, select pretend today `2016-04-24` (real Walmart sales in this dataset end on `2016-05-22`).
3. **Pick an Item:** In the top item dropdown, search and select `FOODS_1_001_CA_1` (or any item from `FOODS`, `HOBBIES`, or `HOUSEHOLD`).
4. **Inspect Forecasts (/forecast):**
   - Click **Forecast** in the left sidebar.
   - Toggle between **7 Days** and **28 Days**.
   - Review the Recharts graph showing real historical sales (solid line) and model predictions (dashed line).
   - Review the peak day and expected sales total cards.
5. **Inspect Anomalies & Calculate Reorder (/anomalies and /reorder):**
   - Click **Anomalies** to view past demand spikes and drops with reason tags (price change, SNAP, event).
   - Click **Reorder**, enter `Current Stock: 5` and `Lead Time: 5 days`, then click **Get Advice**.
   - Observe the safety stock, reorder point, days of stock left, and recommended replenishment order quantity.

## 7. Troubleshooting

- **Model fails to load (joblib / pickle error):**
  - Make sure Python package versions match Colab: `lightgbm==4.6.0`, `scikit-learn==1.6.1`, `pandas==2.2.3`, `numpy==2.4.6`, `joblib==1.6.0`.
  - Check `backend/requirements.txt` and install the exact versions inside your virtual environment.
- **Missing Data Files (503 Service Unavailable):**
  - Visit `http://localhost:5000/debug/status` to see which files are missing.
  - Download the missing files from the shared Drive folder `for_backend` and place them into `backend/data/` and `backend/models/`.
- **CORS Error in Browser:**
  - `flask-cors` is enabled on the backend in `app.py` via `CORS(app)`.
  - If calling from a custom frontend origin, ensure `flask-cors` is installed and backend is restarted.
- **Port 5000 or 5173 Already in Use:**
  - On Windows, find the blocking process: `netstat -ano | findstr :5000` and terminate it with `taskkill /PID <PID> /F`.
  - Alternatively, change the port in `backend/app.py` or pass `--port <new_port>` to `npm run dev`.
